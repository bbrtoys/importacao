# Fluxo de trabalho

- Por preferência expressa do usuário, ao concluir e validar um ajuste solicitado neste projeto, faça commit dos arquivos envolvidos e envie para `origin/main`. O GitHub Pages publica o site após o envio. Não solicite nova confirmação para essa publicação rotineira, salvo instrução posterior do usuário.
- Publique somente ajustes concluídos e validados; salvar um arquivo durante a edição não deve iniciar uma publicação.
- Preserve alterações alheias à tarefa, sincronize com o remoto antes de publicar e não use force push.
- Confira se a versão publicada contém o ajuste antes de informar que ele já está no ar. Se houver falha de autenticação ou publicação, informe o estado real.
- O site local usa o banco Supabase de produção. Valide alterações de interface sem criar ou modificar dados reais.

# Apresentação dos números

- Por preferência expressa do usuário, exiba valores e quantidades completos em todas as telas, cartões, gráficos e dicas. Não abrevie com “mil”, “mi”, “k” ou notação compacta. Use separadores pt-BR; valores monetários devem incluir R$ e duas casas decimais. Adapte o layout para acomodar o número completo.

# Legibilidade

- Nos painéis de pedidos e de itens, use `0.9375rem` (15px na configuração padrão) para textos e tabelas e `0.875rem` (14px) como mínimo para rótulos, legendas e cabeçalhos, com entrelinha de 1,5. Títulos e indicadores ficam maiores, sem exagero: o usuário achou 16px com números grandes pesado demais. Preserve fontes relativas, contraste e zoom; reorganize os cartões em telas menores em vez de reduzir a fonte. Essa é uma decisão de legibilidade do projeto, não uma declaração de conformidade integral à ABNT NBR 17225.
